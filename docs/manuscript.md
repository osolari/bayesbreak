# Manuscripts

## Research paper

The single-column research paper source is in
[`docs/manuscripts/paper/main.tex`](https://github.com/osolari/bayesbreak/tree/main/docs/manuscripts/bayesbreak-paper/paper)
(symlinked from `docs/manuscripts/paper/`). It is a self-contained LaTeX
project maintained in Overleaf and mirrored here.

Build with:

```bash
make -C docs/manuscripts paper
```

The paper includes completed E00–E10 experimental results integrated from
verified run records. The E00 exactness-check subsection (§E00) documents
380 oracle checks, all passed. E09 (real-data analysis) passed its execution
gate; scientific completeness is incomplete — see [Results](results.md) for
the full breakdown.

## Companion technical book

The companion technical book source is in
[`docs/manuscripts/book/main.tex`](https://github.com/osolari/bayesbreak/tree/main/docs/manuscripts/bayesbreak-book/book)
(symlinked from `docs/manuscripts/book/`).

Build with:

```bash
make -C docs/manuscripts book
```

The book covers mathematical background and extended derivations not in the
paper. It shares a bibliography with the paper but maintains its own figure
assets.

## Shared assets

Both packages share a bibliography in `docs/manuscripts/shared/bibliography/`.
The paper's figures are in `docs/manuscripts/shared/figures/` and are
generated by the two-stage pipeline:

```bash
# Stage B: render figures from cached CSV/JSON (~10 s, no inference)
python scripts/figures/render.py --all

# Stage A: rebuild CSV caches from experiment artifacts (slow)
python scripts/figures/prepare_data.py --all
```

Stage B writes outputs to `docs/manuscripts/paper/figures/`. It reads only
from `docs/manuscripts/shared/figures/data/` and never modifies
`results/confirmatory/`.

## Overleaf synchronisation

Both manuscripts are connected to Overleaf via the git integration. Always
run `overleaf_sync.sh compare <name>` before pushing to avoid overwriting
Overleaf-only files. See the `overleaf` skill (`.claude/skills/overleaf.md`)
and `docs/guides/overleaf_runbook.md` for the full workflow.

## Future numerical updates

Any numerical update to a reported result must come from a verified run record
following the frozen E00–E10 protocols. Do not infer or adjust reported
numbers manually; rerun with corrected code and verified data, then update the
corresponding figure cache.
